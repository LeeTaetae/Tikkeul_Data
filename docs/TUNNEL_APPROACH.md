# 터널 접근 감지 · 기상 연동 (GPS 기반)

터널 입구에 가까워질 때 GPS 만으로 접근을 감지하고, 기상청 관측값(비·눈·저온)을 결합해 "미끄러울 수 있다"는 사전 안내를 낼 수 있게 한 **로직 계층**이다. iOS·Android 가 같은 JS 코드를 쓴다.
설계 근거와 데이터 검증은 `ai/tunnel_detection/docs/`(INTEGRATION_READINESS, LIVE_API_VERIFICATION 등)에 있고, 이 문서는 **앱에 들어간 것과 연동 방법**만 적는다.

## 1. 데이터 구조와 "입구 좌표" 정책

원천: 국토교통부 도로 터널 현황(btiData) 2025 — 이용허락범위 제한 없음(앱에 쓸 때 출처 표시를 권장). 가공: `ai/tunnel_detection/scripts/export_app_tunnels.py` → `frontend/src/data/tunnelEntrances.json`(444KB).

```
TunnelFacility { id, name, baseName, roadType, roadName, direction, lengthM,
                 a: 기록의 시점, b: 기록의 종점, groupId: 같은 시설의 다른 관(쌍굴)끼리 같은 값 }
```
기록은 시점/종점만 있고 "어느 쪽이 입구인지"는 없다. 입구는 **차량 진행 방향**이 터널 축과 맞는 쪽이다(반대 차로 기록·시점/종점이 뒤집힌 기록도 방향으로 처리).

**거리 경고 대상은 입구 좌표를 정확히 아는 시설뿐이다.**

| 분류 (전국 4,003개) | 개수 | 앱에서 |
|---|---|---|
| 정밀(양 끝점이 서로 다름) | **1,852** | 거리 경고 대상 (고속국도 307 · 일반국도 858 · 시도 189 · 특별시도 171 · 지방도 134 · 국가지원지방도 133 · 군도 51 · 구도 9) |
| 대표 좌표(시점=종점) | 1,008 | **제외** — 점이 입구인지 중앙인지 알 수 없다(PoC 실측: 일관되게 입구도 중앙도 아니다) |
| 좌표 없음 | 173 | **제외** |
| 한쪽 끝점만 | 1 | **제외** |
| 직선거리가 연장보다 지나치게 긴 기록 | 18 | **제외**(좌표 오류 의심) |

## 2. GPS 접근 감지 (`approach.ts`)

입력: GPS 점(위도·경도·정확도·시각). 진행 방향·속도는 최근 점들의 이동에서 직접 구한다(`MotionEstimator`) — expo-location 의 heading 에 의존하지 않아 iOS·Android·카카오 네이티브 위치 이벤트(방향 없음) 모두 같은 코드로 처리된다. 12m 이상 움직이지 않았거나 정확도 50m 초과인 점은 방향 판단에 쓰지 않는다.

판정(입구 후보마다):
1. 진행 방향이 터널 축(입구→출구)과 60° 안 — 아니면 그 끝은 출구이거나 반대 차로다.
2. 입구까지 1.1km 안.
3. 입구 앞(또는 막 지남)에 있어야 한다. 입구 100m 이상 안쪽이면 대상 아님.
4. 150m 밖: 입구를 향해 45° 안이고, 진행선이 입구를 비껴가는 거리가 `40m + 0.15×거리` 안. 150m 안: 터널 축에서 옆으로 25m(+GPS 오차 절반) 안.
5. 경로가 있으면(`makeRouteFilter`) 입구가 경로에서 30m 안이고 방향이 같아야 한다.

**한계 (테스트로 확인한 사실)**: 경로 없이는 같은 방향으로 평행한 길이 멀리서는 통과한다(400m 앞 60m 옆 도로 → 통과, 100m 넘게 비껴가면 거름). 입구 150m 안에서 걸러진다. 정확도를 높이려면 카카오 안내 경로로 `makeRouteFilter` 를 쓴다. 임계값은 PoC 초안이다.

## 3. 기상 판단과 백엔드

### 서버 `GET /api/weather/road?lat&lon`
- 기상청 단기예보 조회서비스 `getUltraSrtNcst`(초단기실황)를 서버에서만 호출한다. 키 `KMA_SERVICE_KEY` 는 `backend/.env`(Git 제외)에 둔다. 앱 번들에는 키가 없다.
- 기상청에는 **좌표가 아니라 격자(nx, ny)** 만 보낸다. 캐시도 격자 단위(5km), TTL 10분. 업스트림이 실패하면 30분까지 마지막 성공 결과를 `meta.stale=true` 로 내준다.
- 발표 규칙: (지금−10분)을 10분 단위로 내린 시각부터 조회, 자료 없음(03)이면 10분씩 최대 4번 거슬러 올라간다. 모두 없으면 503 `WEATHER_UNAVAILABLE`.
- 응답: `observed_at, temp_c, rain_mm_1h, pty, humidity_pct, missing[], grid, meta`. 결측(|값|≥900)은 null + `missing`. 모르는 PTY 코드는 추측하지 않고 `unknown` + `missing=['PTY']`.
- 오류는 모두 앱의 기존 오류 형식(`{error:{code,message}}`)이다: 키 없음 `NOT_CONFIGURED`, 인증 `UPSTREAM_AUTH`, 한도 `UPSTREAM_RATE_LIMIT`, 시간 초과 `UPSTREAM_TIMEOUT` 등.
- 공유 파일 변경은 모두 **추가만**: `config.py`(+5줄), `errors.py`(+1), `main.py`(+4), `upstream.py`(+29, `kma_nowcast`), `.env.example`(+3).

### 앱 `weather.ts`
| 관측 | 결과 |
|---|---|
| 눈 계열(눈·비/눈·빗방울눈날림·눈날림) | warning |
| 비 계열 + 기온 ≤3℃ | warning (비·저온) |
| 비 계열 + 기온 >3℃ 또는 기온 결측 | caution |
| 강수 없음 + 기온 ≤2℃ + (1시간 강수>0 또는 습도≥80%) | caution |
| 그 밖 | none |
| 관측 없음 · 60분 초과 · 미래 시각 · 강수형태(PTY) 결측 | **unknown** |

- **노면 결빙을 확정하지 않는다.** `basis` 는 항상 `weather_only` 이고, 결과에 "결빙/얼음" 같은 표현이 없다(테스트가 확인). 문구는 "미끄러울 수 있음"까지만 쓴다. 춥지만 건조하면 `none`.
- **unknown 은 "안전"이 아니다.** unknown/none 이면 경고를 내지 않지만, 터널 접근 자체는 이벤트로 알린다. 화면에 "기상 정보 확인 불가"를 따로 보일지는 UI 의 몫이다.

## 4. 경고 정책과 중복 방지 (`alert.ts`, `watcher.ts`)

단계 거리: 기본은 속도 적응형(80km/h 에서 caution ≈550m, approach ≈310m, final ≈155m; 100km/h 에서 ≈690/390/190m). 느린 속도에서는 기존 앱의 고정 거리(500/300/100m)보다 가까워지지 않는다. `thresholdMode: 'fixed'` 로 기존 거리를 쓸 수 있다. 적응형을 쓴 이유: 고정 100m 는 100km/h 에서 3.6초라 음성이 입구에 늦는다(PoC 계산). 리드 시간(25/14/7초)은 **가정값**이고 실측하지 않았다.

| 조건 | 배너 | 음성 | 진동 |
|---|---|---|---|
| unknown / none | 없음 | 없음 | 없음 |
| 20km/h 미만 | 없음 | 없음 | 없음 |
| caution(비) | 있음 (200m 미만 터널은 없음) | 없음 | 없음 |
| warning(눈·비+저온) | 있음 | **시설당 1회**, 입구 8~30초 전일 때만, 터널 음성 사이 90초 쿨다운 | **final 단계만** |
| 앞 터널 출구에서 1km 안의 이어지는 터널 | 있음 | 없음 | 없음 |

중복 방지:
- 시설(그룹) 단위로 단계를 한 번씩만. GPS 가 요동쳐도 되돌아가지 않고, 공백으로 먼 단계를 건너뛰면 가까운 단계만 낸다.
- 쌍굴(이름이 같고 끝점이 150m 안)은 한 시설로 합친다. 같은 방향으로 입력된 두 기록(전체의 13%)에서도 경고는 한 번.
- 입구를 20m 넘게 지나면 `cleared`(배너 내리기)를 한 번 내고 그 시설은 끝. 3km 넘게 멀어지면 이력을 잊어 다시 지날 때 새로 알린다.
- 터널 안에서 GPS 가 끊기면 `cleared` 가 오지 않을 수 있다(알림은 이미 한 번만 나갔으므로 중복은 없다).

## 5. 실제 연동 방법 (아직 안 했다)

`createTunnelWatcher(loadBundledTunnels().index)` 를 만들고, GPS 점이 올 때마다 `update(fix, weather, Date.now())` 를 부른다. 반환된 `TunnelEvent[]` 의 `presentation` 으로 UI 를 구동한다.

- **GPS 입력**: ① 카카오 네이티브 안내 중에는 `nativeGuidanceFeed.parseNativeLocation` 의 `NativePosition`(lat, lng, accuracyM, speedMps) → `GpsFix{lat,lng,accuracyM,timestampMs}`. ② 그 밖(홈 주행 등)에는 `expo-location` `watchPositionAsync`. 경로가 있으면 `makeRouteFilter(route)` 를 `entranceFilter` 로 넘긴다.
- **기상**: 5~10분마다(또는 격자가 바뀔 때) `GET /api/weather/road` → `parseRoadWeather` → watcher 에 전달. 실패하면 `null` 을 넘긴다(unknown).
- **음성·진동**: 기존 `speak(text, { source: 'hazard' })` 와 진동 호출을 그대로 쓴다. `presentation.tts`/`haptic` 이 true 일 때만.
- **우선순위**: 터널 경고는 P1 상한(P0 금지)이다 — `hazardPriority.ts` 점수표에 유형을 추가하고, 같은 순간 음성이 겹치면 객체 충돌 > 어린이보호구역 > 사고·통제 > 터널 순(PoC 제안, 앱 팀 검토 필요). **이 파일은 이번에 수정하지 않았다.**
- **문구(ko/en/zh)**: 이벤트의 `stage`, `risk.reasons`(rain/snow/low_temp/wet_or_humid), `distanceM` 으로 만든다. "사고·충돌 확정"이 아니라 "위험 가능성/주의"로 쓰고(팀 규칙), **"얼었다/결빙"은 쓰지 않는다.** 추가해야 할 i18n 키는 단계 3 × 이유(비·눈·비+저온) 정도다.
- **iOS·Android 가능성**: 로직은 순수 JS 라 두 플랫폼이 같다. 필요한 네이티브 변경 없음. 다만 ① 카카오 네이티브 위치 이벤트의 실제 갱신 주기·정확도, ② 백그라운드/화면 꺼짐에서 JS 위치 수신이 유지되는지는 **기기에서 확인하지 못했다**.

## 7. YOLO 터널 입구 탐지 — 데이터 현황 (학습 불가)

**합법적으로 쓸 수 있는 학습 데이터가 현재 0장이다.** 따라서 학습하지 않았다.

- Roboflow `nqtan` 데이터(3,614장): 팀 결정으로 **학습에 쓰지 않는다.** 원본은 그대로 두었고, 새 검사기(`scripts/check_training_readiness.py`)가 출처에 `roboflow`/`nqtan` 이 있으면 무조건 탈락시킨다.
- KRID(CC BY-NC-SA 4.0 → 비영리): 터널 클래스(Polygon, 객체 9,940개)가 있고 국내 도로 전방 영상이다. 샘플 링크는 삭제됐고, 전체는 **설문 제출 + 승인**이 필요하다 — 개인정보 입력·약관 동의라 사용자가 직접 해야 한다. 상업 서비스로 이어질 가능성이 있으면 팀이 사용 범위를 먼저 정해야 한다.
- AI Hub "전국 도로시설물 영상정보"(dataSetSn=71786): 폴리곤 15종에 터널 포함, **내국인 신청·승인** 필요. 라이선스 문구가 페이지에 없고, AI Hub 공통 정책은 AI 학습 목적 이용·상업적 이용 별도 협의·제3자 제공 금지다. KRID 와 같은 데이터인지 미확정.
- 이번 재조사에서 합법 라이선스의 **추가 터널 입구 데이터셋을 찾지 못했다.** 검색에 걸린 것은 전부 Roboflow Universe 였다. Mapillary 거리 영상은 CC BY-SA 4.0 이지만 라벨이 없고 ShareAlike 가 모델에 미치는 범위가 불명확하다(법률 검토 필요).
- 두 데이터 모두 **터널 폴리곤이 "입구"인지 "터널 전체"인지 받아 보기 전에는 모른다.** 박스로 변환하면 입구보다 커질 수 있다.

학습을 시작하려면 최소한 (초안 기준, `check_training_readiness.py`):

| 항목 | 최소 | 비고 |
|---|---|---|
| 터널 입구 이미지(양성) | 1,500장 | Ultralytics 권장(클래스당 1,500장 이상) |
| 서로 다른 장소/영상 | 100개 | 같은 영상의 연속 프레임만 많으면 일반화되지 않는다 |
| 터널 없는 이미지(음성) | 1,000장 | 교량·지하차도·고가·방음벽 등 헷갈리는 구조물 포함 |
| 야간 / 비 / 눈 양성 | 각 150장 | 기상 경고와 연동하려면 악천후·야간에서도 작동해야 한다 |
| test 양성 | 200장 | 학습에 쓰지 않은 장소만 |
| 출처·라이선스 | 전부 기록 | 불명이면 탈락, NC 는 팀 승인 필요 |

현재 판정: `scripts/check_training_readiness.py` → **학습 불가**(이미지 0장). 기준값은 이 프로젝트에서 검증한 값이 아니다.
확보 경로(모두 사용자 신청이 필요한 것 포함): ① KRID 설문 신청, ② AI Hub 신청, ③ 팀 블랙박스 영상 직접 촬영(야간·비·눈 포함, 라이선스 문제 없음), ④ 필요하면 한국 터널 사진 Wikimedia Commons(파일별 라이선스 확인, 평가용 소량).

### 앞으로의 YOLO 연동 지점
`TunnelStageEvent` 에 시각 확인 결과를 더하는 방식이 가장 안전하다: GPS 가 "입구 150m 안"으로 판단한 구간에서만 탐지를 돌려 일치하면 신뢰도를 올리고, 불일치해도 GPS 경고를 막지는 않는다(탐지 실패가 경고 누락이 되지 않게). 이 연동은 **설계만 했고 구현하지 않았다.**

## 8. 미완료 · 필요한 것

1. 화면·음성·진동 연결(훅), ko/en/zh 문구, `hazardPriority` 유형 추가 — 앱 팀 검토 필요.
2. **실주행 검증**: 방향(상·하행) 오판율, 쌍굴·평행 도로 오탐률, 카카오 위치 이벤트로의 접근 거리 정확도. 정답 라벨이 있는 주행 기록이 필요하다.
3. 비·눈·저온 **실관측** 검증(겨울/악천후), 기상청 야간·점검 시간대 지연.
4. 도로 결빙 위험정보 API 연결(연결 전까지는 "미끄러울 수 있음" 이상을 말하지 않는다).
5. 고속국도 점 하나 터널(70%)의 입구 위치 — 독립 출처(OSM 등) 라이선스·방향 매핑 검토.
6. YOLO 학습 데이터(위 표) 확보 후 학습·평가.
7. `tunnelEntrances.json` 커밋 여부와 갱신 주기(연 1회, btiData 연간 갱신) 결정. `KMA_SERVICE_KEY` 를 운영(Render) 환경변수에 추가.
