# 테스트 계획

테스트 도구·명령어는 코드가 생긴 뒤 확정한다 (TBD). 실행하지 않은 테스트는 성공으로 보고하지 않는다.

## 1. 범위와 우선순위

P0 기능을 먼저 검증한다. P1, P2는 구현될 때 항목을 추가한다.

## 2. 테스트 항목

| 요구사항 | 구분 | 시나리오 | 통과 기준 |
|---|---|---|---|
| F-01 | 비전 | 객체가 있는/없는 샘플 영상 입력 | 대상 객체 탐지, 없는 영상은 오탐 없음 (목표 수치 TBD) |
| F-02 | 비전/로직 | 객체가 ROI 안/밖에 있는 입력 | ROI 안에서만 경고 발생 |
| F-03 | 로직 | 보호구역 안/밖, 시간대 조합 | 조합별로 정의된 경고 수준과 일치 (규칙 확정 후) |
| F-04 | 백엔드/연동 | 교통 정보 조회 | 응답 형식 검증 통과, `updated_at` 포함 |
| F-05 | 백엔드/연동 | 보호구역 근접 좌표 | 안내 표시 |
| F-06 | 프론트 | ko/en/zh 전환 | 번역 누락·키 노출 없음 |
| F-07 | 프론트/연동 | 네트워크 차단 | 장애 표시와 마지막 갱신 시각 표시, 앱 중단 없음 |
| N-01 | 보안 | 네트워크 트래픽 점검 | 카메라 영상/프레임이 전송되지 않음 |
| N-04 | 보안 | 로그 점검 | 좌표·토큰 등 민감정보 없음 |
| N-05 | 문구 | 경고 문구 검토 | 사고·충돌 확정 표현 없음 |
| 보안 | 저장소 | 추적 파일 점검 | `.env`, `*.key`, `*.pem` 등이 Git에 없음 |

## 4. 완료 기준

- P0 시나리오(F-01 ~ F-07)가 모두 실행되어 통과했다.
- 실패 항목은 원인과 담당자가 기록되어 있다.
- 실행하지 못한 항목은 "검증 못 함"과 이유가 적혀 있다.
- PR마다 실행한 테스트와 결과가 적혀 있다.

## 5. 버그 처리

가능하면 재현 테스트를 먼저 작성하고 수정한다. 수정 전후 결과를 PR에 적는다.
