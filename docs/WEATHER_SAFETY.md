# 기상 기반 주행 안전 안내

기존 YOLO·터널 후보 탐지는 계속 실행한다. 날씨는 탐지 실패나 실제 노면 결빙을 확정하는 근거로 사용하지 않는다.

## 서버

- 기존 `/api/weather/road` 유지. 새 `/api/weather/safety?lat=...&lon=...`는 관측·초단기예보·단기예보를 분리한다.
- 공식 서비스: https://www.data.go.kr/data/15084084/openapi.do
- 공식 항목 설명: https://apihub.kma.go.kr/apiList.do?seqApi=10&seqApiSub=286
- `backend/.env`의 `KMA_SERVICE_KEY`에 공공데이터포털 **일반(Decoded)** 키를 설정하고 서버 재시작. APIHub authKey와 혼용하지 않는다.
- 실황 60초, 예보 300초 격자별 캐시. 오류도 같은 기간 캐시하여 반복 재시도를 막는다. 프로세스 내 요청 시작 간격 `KMA_MIN_INTERVAL_S` 기본 0.5초. 여러 서버 프로세스 간 분산 호출 제한은 별도 운영 과제다.
- 기존 HTTP 타임아웃(기본 15초)을 재사용한다. API 인증·타임아웃·결측·오래된 자료는 unavailable/stale로 구분한다.
- RN1/PCP는 mm/h, SNO는 cm/h의 신적설 예보. 범위·미만·이상은 lower/upper/category로 보존한다. 적설 예보는 현재 노면 적설 관측이 아니다.
- 실황 60분, 초단기 발표 3시간, 단기 발표 6시간을 초과하면 사용하지 않는다. 앱은 앞으로 1시간 안의 예보만 위험 판단에 쓰고 예보임을 표시한다.

## 앱과 임계값

- `src/lib/weather/safety.ts`의 `WEATHER_SAFETY_POLICY`는 **시연용 설정**, 기상청 공식 특보 기준이 아니다.
- 강한 비: 관측 강수량 하한 10mm/h 이상. 눈 계열: 관측 강수량(물 환산) 하한 1mm/h 이상. 모델 정확도 저하량을 측정한 값이 아니다.
- 3℃ 이하 + 강수/신적설 조건은 결빙 **가능성** 안내. 강수 없는 저온·습도만으로 시설 위험을 만들지 않는다.
- 확인된 터널 양 끝점과 실제 경로를 기하학적으로 매칭한다. 터널 내부는 입구 경고를 반복하지 않고 출구 500m/100m에서 출구 안내를 생성한다. 평행도로·고가/지하 구분 및 실제 터널 GPS 수신은 실주행 검증이 필요하다.
- 교량은 기존 국토교통부 BTI 2025 원본 40,597건에서 국내 양 끝점, 연장 100m 이상, 직선거리/연장 0.8~1.2를 통과한 **5,509건**만 별도 위치 목록으로 준비했다. 원본 해시·출처·수집 시각을 함께 기록했고 원본은 변경하지 않았다. `endpointsVerified`는 이 기하학적 검사 통과를 뜻하며 현장 실측 검증은 아니다. 방향 코드 의미를 추측하지 않고 실제 경로의 순서를 사용한다. 테스트의 가상 교량은 제품 위치 자료에 포함되지 않는다.
- GPS 15초 초과·정확도 50m 초과·경로 이탈 40m 초과 시 시설 경고를 해제한다. 네이티브 SDK의 정확도 미제공 시에는 명시적 posTrust=true를 요구한다. SDK 위치 시각은 수신 시각을 사용하므로 원측정 지연 검증은 남아 있다.
- 재탐색 시 시설 단계 이력을 초기화한다. 같은 시설·위험·500m/100m 단계는 중복 안내하지 않는다.
- 상단 배너를 사용하고 왼쪽 위험 아이콘 레일에는 기상을 넣지 않는다. 기존 긴급 경고가 활성화되면 기상 배너·음성을 보류한다.
- JS 길안내 화면은 기존 speaker를 통해 한/영/중 안내를 재사용하며 다른 앱 음성이 재생 중이면 보류한다.
- 네이티브 차량 SDK의 음성 우선순위와 Expo TTS는 공유되지 않는다. 이 화면은 배너와 `onWeatherSpeechEvent` 이벤트만 제공하고 **기상 음성 자동 재생은 하지 않는다**. 별도 TTS 엔진을 만들지 않았다.

## 검증 범위

모의 API, 순수 상태 기계, 기존 위험/카메라 테스트 및 Android 컴파일로 확인한다. 실기기 표시·음성·실주행·iOS 빌드는 별도 검증 대상이다. 실제 KMA 호출은 키가 설정된 경우에만 한 지점에서 수행한다.

## 카메라·경로 결합 정책

- 카메라 후보는 기존 모바일 밝기·형태 휴리스틱의 결과이며 학습된 YOLO 결과가 아니다. 박스·점수·JS 탐지 시각을 메모리에서만 공유한다. 프레임 원본을 저장하거나 서버로 보내지 않는다.
- 카메라 단독은 `터널 후보 감지`, GPS·경로 단독은 `전방 터널 구간`, 최근 양쪽 근거가 있으면 `경로상 터널 접근 중 · 카메라 후보 감지`로 표시한다.
- 결합은 **시설 수준의 잠정 연관성**이다. 카메라 보정·영상/도로 투영이 없으므로 `preferredCandidateIndex=null`, 개별 포털 대응은 항상 미확인이다. 두 후보를 임의로 하나로 줄이지 않는다.
- 후보 유효시간 1.5초, 카메라와 GPS 시각 차이 최대 3초. 카메라 시각은 실제 센서 촬영 시각이 아니라 JS에서 후보를 계산한 시각이다.
- GPS 이동량이 12m 및 위치 정확도의 두 배 이상일 때 진행 방향을 추정한다. 추정 방향이 경로와 60도 이내이고 근거가 10초 이내일 때만 시설 수준 카메라 결합을 허용한다. 방향을 모르면 GPS·카메라 근거를 별도로 표시한다.
- 시설 양 끝점과 중간점, 경로 진행 순서·방향·거리 비율을 확인한다. 경로 밖 시설·역방향 이동은 제외한다. 중복 좌표를 제거하고 평행 시설의 매칭 차이가 8m 미만이면 선택을 보류한다. 고가/지하·평행도로의 실제 통과를 보장하는 지도 링크 ID 또는 현장 검증은 아직 없다.
- 시설 접근 500m에서 진입하고 540m까지 유지한다. 100m 단계는 통과할 때까지 유지하며, 통과는 시설 끝점보다 20m 지난 뒤 확정한다. 터널 내부에서는 입구 안내를 다시 만들지 않는다. GPS 이탈 시 표시를 해제하고 재탐색 시 상태와 이력을 초기화한다.
- 맑은 날에는 시설 위치 안내만 하고 결빙 위험을 만들지 않는다. 위치 안내는 500m에서 한 번, 비·눈에 의한 위험은 필요 시 100m에서 재안내한다. 카메라 후보 변화만으로 동일 시설·단계의 TTS를 반복하지 않는다.
- 날씨 API·기존 위험 우선순위·네이티브 차량 SDK의 음성 이벤트 전용 정책은 유지한다. 본 결합 로직은 mock 회귀 검사 대상이며 실기기·실주행 검증은 아직 하지 않았다.
