# ADR 0001: 기술 스택

- 상태: 채택 (팀이 정한 스택). 세부 항목은 TBD
- 날짜: 2026-10-27

## 배경

4명이 7일 안에 모바일 교통안전 보조 서비스를 만든다. 카메라 기반 객체 탐지, GPS, 교통 공공데이터, 다국어 경고가 필요하다. 일정이 짧아 하나의 언어·도구로 공유할 수 있는 범위가 클수록 유리하다.

## 결정

| 영역 | 선택 |
|---|---|
| 앱 | React Native, Expo, TypeScript, Expo Router |
| 웹 데모 | Expo Web, Vercel |
| 백엔드 | Python, FastAPI, Pydantic |
| 비전 | YOLO, OpenCV |
| 다국어 | i18next |
| 위치 | GPS |
| 경고 | TTS, 화면 경고, 진동 |

## 선택 이유

- Expo: 모바일 앱과 웹 데모를 한 코드베이스에서 만들 수 있다.
- TypeScript: API 응답 타입을 명시해 프론트-백엔드 불일치를 줄인다.
- Python + FastAPI: YOLO·OpenCV 같은 비전 생태계와 같은 언어이고, Pydantic으로 요청·응답 검증이 쉽다.
- i18next: 한/영/중 문구를 키로 관리한다.

## 검토한 대안 (작성자 정리, 팀 합의 아님)

| 대안 | 장점 | 채택하지 않은 이유 |
|---|---|---|
| 네이티브(Swift/Kotlin) | 카메라·성능 제어 | 두 플랫폼 개발 부담, 7일 일정에 부담 |
| Flutter | 단일 코드베이스 | 팀 스택(TS)과 다름 |
| Flask / Django | Python 백엔드 | FastAPI가 Pydantic 검증과 자동 문서를 기본 제공 |

## 영향과 위험

- Expo에서 YOLO를 기기 내 실행하려면 네이티브 모듈이 필요할 수 있다. Expo Go만으로 불가능할 가능성이 있다. (확인 필요)
- Expo Web에서는 카메라·센서·TTS·진동 지원이 앱과 다를 수 있다. 웹 데모 범위는 TBD.
- 영상 비전송 원칙을 지키려면 비전을 기기에서 돌리거나 로컬 처리해야 한다. 아래 TBD 참고.
