# 즐겨찾기 카테고리 접기/펴기 + 카테고리 빠른 선택 design

## 의도 / 왜
커스텀 즐겨찾기 카테고리에 항목이 많아지면(예: 100개) 목록이 한없이 길어진다. 카테고리를 접어둘 수 있게 하고, 새 장소를 등록할 때 이미 쓰던 카테고리 이름을 다시 타이핑하지 않고 바로 고를 수 있게 한다.

## 범위
- `app/favorites.tsx`의 카테고리 그룹(`groupedByCategory`)에 접기/펴기 토글 추가. 기본값은 **접힘**(100개짜리 카테고리가 화면을 다 차지하지 않게).
- 카테고리 헤더를 누르면 지금처럼 홈 화면 지도로 이동하는 동작은 그대로 둔다 — 접기/펴기는 **별도 쉐브론 버튼**으로 둔다(사용자 확인 완료).
- "장소 추가" 폼(`AddFavoriteCard`)에서 `kind === 'custom'`일 때, 이미 쓰고 있는 카테고리 이름들을 칩(Chip) 목록으로 보여주고 누르면 카테고리 입력창에 바로 채워진다. 새 카테고리 이름을 직접 타이핑하는 기존 입력창은 그대로 둔다(칩은 지름길일 뿐, 필수 아님).

## 기존 코드 (재사용 대상)
- `src/components/ui/MenuSheet.tsx:218-229`의 `sourcesOpen` 토글 패턴(`ChevronUp`/`ChevronDown`, `accessibilityState={{ expanded }}`) — 접기/펴기 버튼에 그대로 재사용.
- `app/favorites.tsx:56-64`의 `groupedByCategory` — 이미 카테고리별로 묶여 있음, 바뀌는 건 "항상 펼침"을 "토글 가능"으로 바꾸는 것뿐.
- `app/favorites.tsx:112-118`의 지도 이동 로직 — 그대로 유지, 헤더 `Pressable`은 안 건드리고 그 옆에 쉐브론 버튼만 추가.
- `src/components/ui/Chip.tsx` — 이미 `kind` 선택(집/회사/즐겨찾기)에 쓰고 있는 컴포넌트, 카테고리 빠른 선택에도 그대로 재사용.

## 결정된 사항
- **접기/펴기 기본값은 접힘.** 사용자가 걱정한 "100개짜리 목록"이 화면에 바로 나타나지 않게 한다. 상태는 화면 로컬(`useState<Set<string>>`)로만 두고 저장하지 않는다 — 화면을 나갔다 들어오면 다시 기본값(접힘)부터 시작.
- **헤더 탭 = 지도 보기(기존 그대로), 쉐브론 탭 = 접기/펴기(신규).** 두 동작을 분리해서 기존 기능을 안 건드린다(사용자 확인 완료).
- **카테고리 칩은 추가 전용, 필수 아님.** 칩을 눌러도 입력창 값만 바뀔 뿐이라, 그 뒤에 사용자가 직접 수정해서 새 카테고리로 저장할 수도 있다.
- **칩 목록 출처**: 현재 로드된 `items`에서 `category`가 있는 커스텀 즐겨찾기들의 고유 카테고리 이름(`groupedByCategory`의 키). 새 백엔드 호출 없음.

## Non-goals / Anti-goals
- 카테고리 접힘 상태를 기기에 저장(AsyncStorage 등)하지 않는다 — 화면 재진입 시 항상 접힘부터.
- 카테고리 이름 자동완성(타이핑 중 유사 카테고리 추천)은 범위 밖 — 칩은 고정 목록만 보여준다.
- 카테고리 관리(이름 변경·삭제 전용 UI)는 범위 밖(기존 설계 결정 유지, `2026-11-02-favorite-categories-design.md` Non-goals 참고).
- 즐겨찾기 개수에 따른 가상 스크롤(virtualization)은 범위 밖 — 접기/펴기만으로 100개 문제를 해결한다고 보고, 성능 문제가 실제로 생기면 별도로 다룬다.

## 빌더에게 남기는 것
- 쉐브론 버튼의 정확한 위치(헤더 오른쪽 끝)와 터치 영역 크기는 구현자 판단, `MenuSheet.tsx`의 기존 터치 영역 관례를 따른다.
- 카테고리 칩 목록을 카테고리 입력창 위/아래 어디에 둘지는 구현자 판단, 기존 `kindRow`(집/회사/즐겨찾기 칩) 레이아웃과 시각적으로 구분되게 배치한다.
- 카테고리가 하나도 없는 신규 사용자에게는 칩 목록 자체를 안 보여준다(빈 칩 줄은 혼란만 줌).
