# AI 챗봇 어시스턴트 설계 (짧은 설계)

## 의도
실제 내비 앱들처럼, 사용자가 타이핑이나 음성으로 질문하면 답해주는 챗봇. 두 종류 질문을 다룬다.
- 실시간형: "지금 이 길 위험구간 있어?", "앞에 정체야?" → 현재 위치/경로 기준으로 실제 데이터 조회
- 일반형: "보호구역이 뭐야?", "정체 아이콘 무슨 뜻이야?" → 위치와 무관한 설명

## 목표 / 비목표
- 목표: 타이핑 입력, 음성 입력(STT), 음성 응답(TTS), 실시간+일반 질의 모두 지원
- 비목표: 자유 대화형 범용 챗봇(날씨·잡담 등 서비스 범위 밖 질문 응대) — 교통안전 앱 기능 범위로 한정
- 안티골: AI가 사고·위험을 확정적으로 말하는 것(CLAUDE.md 보안 규칙 — "위험 가능성", "주의" 식으로만 표현)

## 제약
- 7일 일정, 신규 기능이라 범위를 좁게 유지
- 기존에 LLM 연동 코드 없음(신규 의존성: `anthropic` SDK)
- 비용: Claude Haiku 기준 질문 1건 1~2원 수준(허용 가능)

## 접근 방식 (검토 후 결정)
- **A. Claude 툴 호출(함수 호출) 방식 ← 선택.** 백엔드 `/chat` 엔드포인트에서 Claude에 기존 API(incidents, caution zones, protection zones, route)를 툴로 등록. 실시간형은 Claude가 툴을 호출해 데이터를 받아 답하고, 일반형은 바로 답함.
- B. 규칙 기반 질문 분류 + LLM은 문장만 생성: 더 예측 가능하지만 질문 유형이 늘수록 분류 규칙을 계속 추가해야 해서 기각.
- 모델: `claude-haiku-5-5` (비용 최소화, 간단한 Q&A에 적합)

## 결정된 사항
- **UI 위치**: 홈 화면(`frontend/app/index.tsx`)의 `fabWrap`(946행) — "내 위치로 이동" `RoundButton` 바로 아래에 챗봇 버튼 추가
- **입력**: 타이핑 + 음성(STT, 기기 내장 음성인식 라이브러리 추가 필요)
- **출력**: 텍스트 + TTS(기존 `expo-speech` 재사용, `frontend/src/lib/speechVoice.ts` 패턴 따름)
- **백엔드 인증키**: `backend/app/config.py`의 기존 `SecretStr` 패턴대로 `anthropic_api_key` 추가. 없으면 해당 기능만 NOT_CONFIGURED 오류.
- **안전 가드레일**: 시스템 프롬프트에 "모르면 모른다고 답하고, 사고·위험을 확정적으로 말하지 않는다" 명시

## 빌더(구현자)에게 맡기는 부분
- STT 라이브러리 구체 선택(Expo SDK 호환 패키지 조사 후 결정)
- 챗봇 UI 세부 레이아웃(바텀시트 vs 풀스크린 등 기존 `BottomSheet` 컴포넌트 재사용 여부)
- 툴 정의 범위(어떤 기존 API를 1차로 노출할지 — incidents/caution/protection zone부터 시작하고 확장)
- 대화 히스토리 저장 여부(세션 내 메모리만 vs DB 저장) — 7일 범위에서는 세션 내 메모리만으로 제안
